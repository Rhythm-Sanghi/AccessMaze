# Discovery, replay and reusable conditions

Continuation baseline: **8e074e7**, recorded 2026-10-10. These are workstation
continuation changes; no onsite development or competition eligibility is claimed.
The earlier 9f3222a provenance boundary remains intact.

## Approved discovery

Enable website discovery after the authored completion assertion. Computed Chromium
accessible names identify unique enabled buttons, links, checkboxes and radios,
ordered by role/name. Every activation requires fresh approval, including actions
that appear harmless. No label-based classifier grants permission to submit data.
Keyboard mode actually attempts the bounded Tab/Arrow path and retains focus evidence;
pointer mode explicitly reports keyboard reachability untested.

Opt in to **Offer separately approved navigation to the configured start** to visit
other root branches. Recovery is itself approved, uses the original URL and the same
origin policy, and consumes an action. It does not undo server effects or restore/replay
forms. Re-enter prerequisites through an authored journey. There is no automatic
reset/replay of potentially consequential external actions.

Focus-normalized observation keys deduplicate action coverage; original focus remains
in graph evidence. Previously unvisited alternatives remain persisted across recovery.
Depth, total actions and the enclosing journey wall-clock bound execution, including
approval waits. Partial observations survive cancellation/crash. AX discovery is
bounded to 500 nodes/depth 8, 100 candidate names inspected and 30 enabled actions offered.
Disabled/ambiguous/unsupported controls and unseen application states are not proven
accessible or inaccessible. Budget exhaustion records untested paths, never a barrier.

## Historical evidence and live reproduction

Open a run with findings. **Failure reproduction** selects a stored finding and shows
its authored action, expected/observed result, original step trace and relevant state
and focus evidence. Reading this workspace never re-executes a browser.

Choose **Review browser re-execution**, inspect the historical target, origin permissions,
profile and every step, supply fresh runtime bindings/uploads, then authorize and run.
The worker reconstructs the historical authored definition rather than trusting the
current edited project. Redacted literal inputs become fresh runtime bindings;
credentials cannot be recovered. Each replay uses a new isolated context, persists
source run/finding provenance and actual new execution evidence. Original records
remain unchanged. Exploration is disabled during replay.

The workspace compares old/live step status and focus. `observed-again` means the
same step/rule/available target identity was observed again, not identical site state.
Private axe targets cannot be matched across run-specific privacy tokens and require
review. `not-reproduced-in-this-run` means the relevant step passed without that finding;
it is not certification of repair. Changed sites, blocked traffic, cancellation and
steps not reached are explicit limitations. A privately withheld discovery target
cannot be reconstructed; author/review a journey for that branch before replay.
Normal run-history comparison retains its stricter unchanged-conditions repair rules.

## Profile library

In Journey builder, edit concrete test conditions, name them and save a reusable
profile. Apply it to another project, edit/update it or remove it from the library.
SQLite schema 3 migrates prior projects/runs/retests without deleting them. Each
journey/run keeps a condition snapshot; changing a library entry never rewrites history.
Backups contain the profile table. No credentials or upload payload belong in profiles.

Conditions actually affect Chromium: keyboard-only vs permitted pointer activation,
viewport, reduced motion, bounded request delay, optional final axe semantics audit,
and optional exact role/name completion-focus assertion. Connection interruption and
recovery insert recorded offline/online actions after the two chosen existing step IDs.
Recovery must follow interruption. When reusing across different step IDs, map the two
IDs explicitly; invalid mappings are rejected before launch.

**Layout zoom emulation** (50–200%) changes CSS viewport dimensions and device scale,
with resulting innerWidth/innerHeight/devicePixelRatio saved in observations. It does
not operate browser chrome zoom, text-only zoom or OS magnification. Request delay is
not bandwidth emulation; in-flight responses may finish during a connectivity transition.
Axe/DOM focus evidence is not real screen-reader testing or disability simulation.

To compare profiles, run the same authored journey, apply another profile and run again
with fresh authorization. Select the earlier run in Journey comparison. Actual task
outcomes, step evidence and both profile snapshots can be compared. Changed profiles
make repair verification inconclusive; a pointer success does not repair a keyboard barrier.

## Verification scope

Real browser regressions cover separate multi-page/history-SPA branches, fresh navigation
approval, preserved frontier/no destructive POST, stale approvals, cancellation and
saved observations. Additional actual Chromium regressions reproduce a keyboard
failure, re-execute it, observe a corrected target, test cancelled replay, verify input
redaction/history immutability, profile-dependent outcomes, offline/recovery, motion,
layout zoom metrics, actual semantic audits and completion focus assertions.
Native acceptance and package results are recorded separately in engineering status;
no pending native check or independent release gate is implicitly passed here.
