# Questions and precise answers

**Does a completed journey mean WCAG conformance?** No. It means required assertions
passed in one bounded execution. Rule findings and manual-review requirements remain.

**What is discovered automatically?** Named supported controls and observed state
transitions under finite budgets. External exploration follows one approved path.
Fixture branch search can reset only bundled synthetic applications. No general
natural-language task understanding or exhaustive coverage is claimed.

**How is a repair verified?** Same project, exact journey configuration, runtime input
signature and recorded environment; distinct completed candidate execution; relevant
step passes with no matching rule violation or incomplete axe result. Findings match
stable step ID, rule and exact affected-target set, not array position. Private per-run
target tokens cannot identify the same element across runs.

**What does the profile represent?** Concrete browser settings and allowed interaction
methods. It does not represent every member of a disability group. Real screen-reader
execution requires a human and actual AT; browser AX observations are labeled separately.

**Are credentials stored?** Runtime bindings are ephemeral. Saved literal journey input
is plaintext; use bindings for sensitive input. Evidence redaction is not encryption or
secure erase. Exports inherit destination permissions. See internal security review.

**What happened onsite?** No onsite achievement is asserted. The dated baseline,
commit history and entrant-completed onsite ledger provide the contribution boundary.

**Is the ZIP production-ready?** No. Independent Windows/NVDA/security/distribution
review, remote CI, signing and other documented qualification gates remain open.
